# オペレーショナル・オーディット

## いつ使うか

- 「なぜ売上が落ちてる？」「なぜコストが増えてる？」という原因不明の問題
- 業務プロセスのボトルネック発見
- クレーム増加、離職率上昇など異常値の原因追求

## 鉄則

> **原因を特定せずに対策を打つな。**
> 症状を治しても病気は治らない。

```
× 「売上が下がってるので広告を増やしましょう」
○ 「売上低下の内訳: 新規-15%、既存-3%。新規の商談数は横ばいだが成約率が40%→25%に低下。
   原因: 競合B社が3月に価格を20%下げた。対策は価格対抗ではなく差別化の強化」
```

## ワークフロー

### Phase 1: 事実確認（症状の特定）

1. **何が起きているか** — 数字で。「売上が下がった」ではなく「前月比-12%、前年比-8%」
2. **いつから** — いつ変化が始まったか。月次推移を確認
3. **どこで** — 全体か、特定セグメントか。商品別、地域別、顧客別に分解
4. **どの程度** — 影響の大きさ。金額、割合、トレンド

### Phase 2: 原因分析（なぜなぜ分析）

5回の「なぜ」で根本原因に到達する：

```
なぜ売上が下がった？
→ 新規顧客の獲得数が減った

なぜ新規獲得が減った？
→ 商談からの成約率が低下した

なぜ成約率が低下した？
→ 競合に価格で負けるケースが増えた

なぜ価格で負ける？
→ 競合B社が3月に価格を20%下げた

なぜ競合は価格を下げられた？
→ 製造コスト削減に成功（自動化投資の回収完了）

★根本原因: 競合の原価構造が変わった。価格対抗ではなく価値提案の差別化が必要
```

### Phase 3: 仮説検証

根本原因に対して3つの仮説を立てる：

| 仮説 | 検証方法 | 必要なデータ |
|------|---------|-------------|
| A: [仮説] | [どう確かめるか] | [何を見るか] |
| B: [仮説] | [どう確かめるか] | [何を見るか] |
| C: [仮説] | [どう確かめるか] | [何を見るか] |

### Phase 4: 改善策の提示

```markdown
## 🔍 オーディット結果

### 問題
[1文で端的に]

### 根本原因
[なぜなぜ分析の結果]

### 改善策（優先度順）
1. **即効性あり（今週）**: [具体的アクション] → 期待効果: [数字]
2. **中期的（今月）**: [具体的アクション] → 期待効果: [数字]
3. **構造的（今期）**: [具体的アクション] → 期待効果: [数字]

### モニタリング指標
| 指標 | 現在値 | 目標値 | 確認頻度 |
|------|--------|--------|---------|
| ... | ... | ... | 週次/月次 |

### 次回チェックポイント
[日付] — [その時点で確認すべきこと]
```

## アンチパターン

- 原因不明のまま「とりあえずコスト削減」→ 根本原因を先に特定しろ
- 1つの原因に飛びつく → 必ず3つの仮説を立てろ
- 「業界全体が不況だから」→ 業界内で伸びてる企業は？何が違う？
- データなしで議論 → 数字を出せ。出せないなら「データがない」が最初の課題
