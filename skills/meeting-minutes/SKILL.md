# 議事録作成スキル

## いつ使うか

- 経営者が「議事録を作って」と依頼したとき
- 会議のテキスト・メモ・音声文字起こしが提供されたとき
- 過去の議事録の整理・フォーマット統一が必要なとき

## ワークフロー

### Step 1: 入力テキスト整理
1. 提供されたテキスト（メモ、文字起こし等）を通読
2. 発言者を特定（名前、役職）
3. 議題・テーマを抽出

### Step 2: 構造化
以下の順序で情報を抽出・整理する：

1. **基本情報**: 日時、場所、参加者、議題
2. **決定事項**: 会議で合意・決定されたこと（箇条書き）
3. **アクションアイテム**: 「誰が」「何を」「いつまでに」の3要素を必ず含める
4. **議論の要点**: 主要な議論の流れを要約（発言の逐語録ではなく要点）
5. **次回予定**: 次回の日時・議題

### Step 3: 品質チェック
- [ ] 決定事項が明確に記載されている
- [ ] アクションアイテムに担当者と期限がある
- [ ] 重要な発言が漏れていない
- [ ] 固有名詞（人名、社名、製品名）が正確

## 議事録フォーマット

```markdown
# 📋 議事録: [会議名]

| 項目 | 内容 |
|------|------|
| 日時 | YYYY/MM/DD HH:MM〜HH:MM |
| 場所 | [場所/オンライン] |
| 参加者 | [氏名（役職）を列挙] |
| 議題 | [メインの議題] |

## 決定事項
1. [決定内容1]
2. [決定内容2]

## アクションアイテム
| 担当 | タスク | 期限 |
|------|--------|------|
| 田中 | ○○の資料を作成 | 4/18 |
| 佐藤 | △△の見積もりを取得 | 4/20 |

## 議論の要点
### [議題1]
- [要点A]
- [要点B]
- [結論]

### [議題2]
- [要点]

## 次回予定
- 日時: YYYY/MM/DD HH:MM
- 議題: [予定議題]
```

## HTML出力

HTMLで出力する場合は `templates/minutes.html` テンプレートを使用する。
context に以下を渡す：
- `meeting_title`, `datetime`, `location`, `participants`, `agenda`
- `decisions` (list), `action_items` (list of dict), `discussion`, `next_meeting`

## コツ
- 「決定事項」と「検討事項」を明確に分ける
- 数字・金額・日付は正確に記録する
- 参加者全員に関係するアクションは「全員」と明記する
